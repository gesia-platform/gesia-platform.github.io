Authentication/Notarization

Node permission distribution authentication token via DAO

Developers can deploy smart contracts using an Externally Owned Account (EOA), a process that involves several steps:

  1. Obtain authentication for smart contract deployment: Developers must first obtain authentication tokens for smart contract deployment through the Node Authority DAO. This token signifies approval for the deployment process.

  2. Payment of authentication gas fee: In order to receive distribution authentication tokens, developers must pay authentication gas fee (fee). This fee is used to compensate for the resources required to process transactions and execute contracts on the blockchain network.

  3. Smart contract deployment and gas fee: After securing the authentication token, developers can deploy the smart contract on the blockchain, paying a deployment gas fee in the process.

  4. Rewards from deployed smart contracts: Deployed smart contracts provide rewards to the deploying developer when making internal calls and external calls.

  5. Transfer of EOA's Owner rights: Once the smart contract is successfully deployed, the developer transfers the EOA's Owner rights to an Internal Owned Account (IOA).

  6. Smart contract call approval: Smart contract call approval is determined by an autonomous organization decentralizing node authority through IOA.

  7. Token Burning: Once the issuance of the smart contract is completed, the distribution authentication token is burned.

Users can use smart contracts through an Externally Owned Account (EOA), a process that includes the following steps:

  1. Obtain authentication to use smart contracts: Users must first obtain authentication tokens to use smart contracts through the Node Authority DAO. This token represents prior authorization for the use of a smart contract.

  2. Payment of authentication gas fee: To receive authentication tokens for smart contract usage, users must pay authentication gas fee (fee). This fee is used to compensate for the resources required to process transactions on the blockchain network.

  3. Paying gas fees when using smart contracts: After receiving the authentication token, users can use smart contracts and must pay gas fees in the process. This gas fee covers the computational resources required for the execution of the smart contract.

  4. Developer rewards for smart contract usage: The smart contract used provides rewards to the developer who deployed the smart contract when making internal and external calls.

A central server can issue smart contracts using a Notary Account (NA), and this process includes several steps:

  1. Obtain certification for smart contract issuance: The central server must first receive a notarization token for smart contract issuance through the Node Authority DAO. This token represents pre-approval for the issuance process.

  2. Payment of authentication gas fee: In order to receive an issued authentication token, you must pay the authentication gas fee (fee) to the notary account on the central server. This fee is used to compensate for the resources required to process transactions and execute contracts on the blockchain network.

  3. Voucher smart contract issuance and gas fee: After receiving the issued notary token to the notary account of the central server, a voucher smart contract can be issued, and the issuance gas fee must be paid in this process.

  5. Burning of issued notary tokens: Once the issuance of the voucher smart contract is completed, the issued notary tokens will be burned.
